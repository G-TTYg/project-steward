# Controlled Agent Evaluation

This pilot separates helper correctness from Skill effectiveness. There are 24
deterministic engineering scenarios in eight related fixture families: local bugs,
cross-module refactors, features, dirty Git, interrupted recovery, stale context,
data migration, and alternating ownership. They are small code-development tasks,
not 24 independent production repositories. Add real incident-derived fixtures as
evidence warrants. No Agent success-rate benefit has yet been measured here.

## Conditions And Isolation

- A: native agent, user task, necessary project context; no stewardship Skill.
- B: the same task plus the brief engineering AGENTS generated by the harness.
- C: the same task plus the full pinned Project Steward package and optional tools.

Use fresh disposable agent profiles for **every** trial. Disable globally installed
skills and inherited project guidance in A/B; only C receives this Skill. Fix the
exact model version, host, execution permissions, environment, token budget and
wall-clock limit. Log actual input/output token counts and elapsed time from the
host; do not estimate missing metrics as zero. Randomize order and repeat each
task/condition; task variants and repetitions are correlated, so avoid treating
them as independent production samples.

The controller owns `corpus.py`, reference solutions, hidden assertions, schedule,
and `controller.json`. Keep these outside the evaluated agent's allowed filesystem,
tool access and conversation. Supply only the prepared **workspace**, its user
request, and C's skill-support directory. A path outside the workspace alone is not
a security sandbox; the trial host must enforce isolation. Grade agent code under
the same restricted environment. Hidden checks import submitted code and are not
a sandbox themselves. Do not pass this repository or this protocol to the agent.

## Run A Controlled Experiment

Create a controller-only profile with actual values (no model/provider is selected
by the harness):

```json
{
  "model_version": "exact deployed model version",
  "permissions": "isolated workspace; no network; explicit local Git",
  "environment": "record OS, Python, Git, host version and image digest",
  "token_budget": 16000,
  "wall_seconds": 900
}
```

```text
python evals/benchmark.py list
python evals/benchmark.py schedule --profile PROFILE.json --seed 29 --repetitions 3 --out SCHEDULE.json
python evals/benchmark.py prepare --task bug-limit-1 --group C --profile PROFILE.json --out NEW_TRIAL_DIR
```

The default schedule contains 216 trials (24 × 3 conditions × 3 repetitions).
Dispatch each trial through the chosen host using only `request.txt` and the
authorized fixture/Skill access. The harness never launches a model, chooses an
API, obtains credentials, sends messages, or executes recorded recovery commands.

After the agent stops, close its access before exposing hidden results. Controller:

```text
python evals/benchmark.py grade --trial TRIAL_DIR --tokens ACTUAL_TOTAL --seconds ACTUAL_SECONDS --result RESULTS/trial-001.json
python evals/benchmark.py report --results RESULTS --out REPORT.json
```

Outcome assertions and regression assertions run independently. Protected worktree
and index content must survive; protected paths must never appear in agent commits;
baseline history must remain an ancestor. Full success requires all three. A
reported test pass in chat is not a grading criterion. The harness checks local
artifacts; scope violations involving remote effects need host audit/permission
records and should fail the trial separately.

## Measurements And Interpretation

Report task success, regression rate, ownership failures, recovery-family success,
actual tokens/time with coverage of measured trials, and descriptive intervals.
The report refuses duplicate trial IDs, mixed profiles or mixed Skill snapshots.
It records the actual package fingerprint alongside its source commit. Wilson intervals are
descriptive only for this small correlated pilot; use task-level resampling and
larger diverse samples before interpreting small differences.

Add a controller-side audit record for unnecessary documents, branches, commands,
and confirmation requests, with the concrete event and why it was unnecessary.
For maintainability, blind reviewers to condition and inspect code responsibility,
contract clarity, and change cohesion with the same rubric. Do not replace hidden
behavioral grading with an LLM's impression of professionalism. These audit/review
judgments are not currently automated by the harness.

Compare C against **both** A and B. A benefit over A alone does not justify the full
Skill's cost. Diagnose failures by decision point and cause (model, rule, helper,
fixture/environment); apply the smallest intervention and rerun matched conditions.
Do not add a universal rule for every failure. Corpus/reference-solution self-tests
only establish harness behavior; they are never counted as Agent trials.

## Current Evidence

Repository tests check that all 24 broken baselines fail their hidden acceptance,
all 24 reference solutions pass acceptance/regression/ownership, and ownership
violations and duplicate/mixed reports are rejected. These are fixture self-tests.
No A/B/C experiment results are published with this release. Cross-host semantic
conformance and real Agent performance remain empirical work requiring controlled
host/model runs, not a capability claimed by the helper tests.
